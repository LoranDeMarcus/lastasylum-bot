# Last Asylum Bot

Бот для **Last Asylum: Plague** (пакет `com.phs.global`) в эмуляторе BlueStacks.
Управляет игрой через ADB и OpenCV: смотрит на кадр экрана, узнаёт кнопки по
шаблонам и тапает. Основной режим — фарм боссов «Элитная скверна».

> **Прежде чем ставить.** Это автоматизация онлайн-игры. Правилами такое обычно
> запрещено, и риск блокировки аккаунта — на том, кто запускает. Антибот-защита
> внутри убирает машинные признаки поведения (см. ниже), но никаких гарантий не
> даёт. Решай сам.

---

## Что бот делает

Цикл режима «Элитная скверна»: лупа → вкладка «Элитная скверна» → «Поиск»
(панель босса открывается сама) → «Штурм» → «Начать Штурм». Отправляет, пока
есть свободные отряды. Если энергии не хватает — тратит фиолетовую склянку +50.

**Чего бот не делает — это выставляешь ты, руками, до старта:**

- уровень скверны в диалоге поиска;
- селектор «Время штурма» (1/5/10/30 мин);
- зум карты;
- награды не собирает.

**Когда останавливается:** энергии не хватает на штурм, три провала подряд,
кнопка Stop, файл `STOP` в папке проекта, тревога сторожа экрана.

## Требования

Всё проверено на этой конфигурации. Чем сильнее твоя отличается, тем больше
придётся калибровать (см. «Калибровка под свою игру»).

| Что | Значение | Как проверить |
|---|---|---|
| ОС | Windows 10/11 | — |
| Эмулятор | BlueStacks 5 (проверено `5.22.250.1016`) | Настройки → О программе |
| Android инстанса | 9 (Pie) | `HD-Adb.exe -s emulator-5554 shell getprop ro.build.version.release` |
| Разрешение инстанса | **1920×1080**, DPI **240** | Настройки → Экран; `shell wm size` / `shell wm density` |
| Кадр игры | **1080×1920** (игра портретная) | `python -m tools.grab_screen shot.png` |
| ADB | включён | Настройки → Дополнительно → **Android Debug Bridge** |
| Python | 3.11 (проверено 3.11.9) | `python -V` |
| Язык интерфейса игры | **русский** | — |

**Разрешение и язык — не пожелания, а жёсткие требования.** Все координаты
кнопок зашиты под кадр 1080×1920, а шаблоны кнопок вырезаны из русского
интерфейса. При другом разрешении бот промахивается мимо всего, при другом
языке не узнаёт ни одной кнопки.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

Зависимости: `opencv-python`, `numpy`, `Pillow`, `pytest`. Больше ничего не
нужно — распознавание цифр на своих шаблонах, без Tesseract.

## Настройка под свою машину

Открой `config.py` и проверь два поля:

```python
adb_path: str = r"C:\Program Files\BlueStacks_nxt\HD-Adb.exe"
adb_serial: str = "emulator-5554"
```

**Как узнать свой serial:**

```powershell
& "C:\Program Files\BlueStacks_nxt\HD-Adb.exe" devices
```

```
List of devices attached
emulator-5554   device      <- этот, игра тут
emulator-5584   host        <- служебные, не они
```

Нужен тот, у которого статус `device`. Если список пуст — ADB выключен в
настройках BlueStacks либо инстанс надо перезапустить.

**Проверь кадр перед первым запуском:**

```powershell
.venv\Scripts\python.exe -m tools.grab_screen shot.png
```

Ожидается `shape=(1920, 1080, 3)`. Если числа другие — поменяй разрешение
инстанса в настройках BlueStacks и перезапусти его. Пока это не сойдётся,
дальше идти бессмысленно.

**Сухой прогон — читает экран, но не тапает:**

```powershell
.venv\Scripts\python.exe -m tools.dry_run 3
```

В логе должны быть осмысленные числа: энергия как в игре, отрядов столько же,
сколько в виджете «Отряд N/4». Если энергия читается как ерунда или отряды
всегда 4 — иди в «Калибровку».

## Запуск

```powershell
run_bot.bat                       # двойной клик, GUI + консоль с ошибками
.venv\Scripts\python.exe -m src.app
run_bot_silent.vbs                # без консоли, когда всё уже работает
```

В окне: кнопки **Start** / **Stop**, поле **«Мин. остаток склянок»** (ниже него
бот склянки не тратит), чекбокс **«Отправлять 4-й отряд»** и лог.

Чекбокс по умолчанию снят: бот занимает максимум 3 отряда, четвёртый остаётся
тебе. Переключается на ходу, останавливать бота не нужно.

Текущий остаток склянок вводить не надо — бот читает его из игры («В наличии: N»
в окне энергии после первого рефилла).

Stop срабатывает мгновенно: будит бота из любой паузы и обрывает заход на
ближайшей проверке, не доводя до тапа. Экран при этом может остаться на превью —
так задумано, прибирать за собой после Стопа бот не пытается.

## Антибот-защита

**Человечные тапы и паузы.** Тап приходит в случайную точку внутри кнопки, а не
в одну выверенную координату. Паузы имеют логнормальный разброс и никогда не
короче откалиброванных — базовые значения подобраны под анимации игры, и
укорачивание срывало бы проверки шагов. Выключается флагом `human_enabled`.

**Сторож экрана.** Перед каждой итерацией бот определяет, что перед ним.
Незнакомый экран → 12 секунд ожидания без единого тапа (реклама, подарок,
анимация уходят сами) → один безопасный BACK → если не помогло, стоп со
скриншотом в `reference/anomaly/` и звуковым сигналом. Экран базы — отдельный
случай: бот жмёт «Мир» и работает дальше.

Капчи и человеко-проверки бот **не проходит** — он для того и останавливается,
чтобы позвал человека.

```python
watchdog_action: str = "log"    # 'log' — наблюдение, 'stop' — боевой
```

**По умолчанию стоит `"log"`: сторож пишет в лог и сохраняет непонятные кадры,
но бота не останавливает.** Погоняй так одну сессию 20–30 минут, посмотри, что
он поймал в `reference/anomaly/`, и только потом переключай в `"stop"`. Иначе
рискуешь получить сторожа, который глушит бота на каждом рекламном баннере.

## Калибровка под свою игру

Шаблоны в `templates/` вырезаны из **конкретной** игры: русский интерфейс, эта
версия клиента, кадр 1080×1920. У другого человека мимо может пойти многое.

| Симптом в логе | Что не так | Что делать |
|---|---|---|
| `диалог поиска не открылся` | не узналась кнопка/вкладка | перенарезать шаблон, см. ниже |
| энергия читается как ерунда | сместился `region_energy` | `tools.probe_anchor`, поправить регион |
| `отрядов=4/3` всегда | не читается виджет «Отряд N/4» | `tools.probe_squads` |
| `[сторож]` на нормальном экране | не совпал якорь HUD | `tools.probe_anchor`, порог `hud_energy_threshold` |
| бот тапает мимо кнопок | другое разрешение инстанса | вернуть 1920×1080 / DPI 240 |

**Инструменты калибровки:**

```powershell
python -m tools.grab_screen shot.png              # снять кадр через ADB
python -m tools.crop_template shot.png templates/имя.png   # вырезать мышью
python -m tools.probe_anchor                      # скоры якоря HUD по всем кадрам
python -m tools.probe_squads                      # что бот видит в «Отряд N/4»
python -m tools.probe_state                       # состояние отряда (можно с shot.png)
python -m tools.dry_run 3                         # решения движка без тапов
python -m tools.corruption_run 1 5                # реальный прогон: 1 отправка
```

`crop_template` открывает окно: выдели кнопку мышью и нажми Enter.

Измеренные пороги и регионы записаны в `CALIBRATION.md` — там же видно, какой
запас у каждого якоря, то есть насколько он переживёт мелкие отличия.

## Тесты

```powershell
.venv\Scripts\python.exe -m pytest -q
```

205 тестов. Распознавание проверяется на реальных кадрах игры из `reference/` —
включая те, на которых легко ошибиться: чужой диалог события (не перепутать с
нужным), диалог выхода из игры, потеря соединения, рекламный баннер поверх
интерфейса (диалог обязан узнаваться вопреки ему).

Если правишь координаты или шаблоны — прогоняй тесты, они ловят большую часть
поломок раньше живой игры.
